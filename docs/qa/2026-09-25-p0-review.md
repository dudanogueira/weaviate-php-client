# QA review: P0 connection layer and Python parity (2026-09-25)

**Scope:**
1. The implemented P0 code: connect helpers, `WeaviateClient`, both gRPC transports, the REST transport, and the exceptions.
2. A parity audit of the plan against the Python client's **latest release, v4.23.1**, and unreleased **`main` (eb5546a)**. It enumerated every public class, method, parameter and enum member with an AST script.

**Method:**
- A read-only QA pass with runtime probes on PHP 8.2 (libcurl 7.88.1), PHP 8.4 (libcurl 8.14.1) and ext-grpc 1.84, against Weaviate 1.39.7.
- Two parity audits, one for client-level APIs and one for collection-level APIs.
- Then fixes, each with a regression test.

## Findings and status

| ID | Sev | Finding | Status | Test |
|---|---|---|---|---|
| F1 | P1 | CRLF/LF/NUL in a header value was sent as extra HTTP/2 headers (gRPC metadata injection) | ✅ Fixed. `Headers::normalize` validates names (HTTP token) and values (no CR/LF/NUL), rejects client-reserved keys and list-style arrays, and ignores a user `X-Weaviate-Client` | `HeadersTest` (13 cases) |
| F2 | P1 | Secrets leaked through `var_dump`/`print_r` of the client, `var_export`/`json_encode` of `ApiKey`, exception traces (`zend.exception_ignore_args=0`), and chained Guzzle exceptions that carry the request | ✅ Fixed. See the notes below the table | `SecretRedactionTest` |
| F3 | P2 | A failed `connect(force: true)` left `isConnected() === true`, and old gRPC transports were never closed | ✅ Fixed. | F4 | P2 | Every REST call used `max(query, insert)` (90 s), so a hung server blocked `connect()` for 90 s | ✅ Fixed. | F5 | P2 | Proxy env vars were always honoured (curl, Guzzle, ext-grpc). ext-grpc ignored an explicit proxy and the user agent | ✅ Fixed. Notes on F2:
- `__debugInfo` redacts credentials on the client, both transports and `AdditionalConfig`.
- `ApiKey` keeps the key in a private static `WeakMap`, not in a property, and refuses `serialize` and `clone`.
- `#[\SensitiveParameter]` is on every credential parameter.
- PSR-18 exceptions are no longer chained.

Notes on F8:
- Network or TLS failures become UNAVAILABLE.
- A connect timeout becomes UNAVAILABLE; a timeout after connecting becomes DEADLINE_EXCEEDED.
- Oversize requests and responses become RESOURCE_EXHAUSTED.
- Invalid ext-grpc metadata raises `InvalidInputException`.

### New finding during testing

- **Weaviate reports a missing or invalid API key over gRPC as `UNKNOWN`**, with the message "extract auth: unauthorized: invalid api key", not `UNAUTHENTICATED`. This was verified on 1.39.7 with both transports. RBAC denials correctly use `PERMISSION_DENIED`.
- `GrpcErrors` maps `UNKNOWN` plus that specific message to `AuthenticationException` (`GrpcErrorsTest`).
- Worth reporting upstream.

## Parity audit summary

**Collections scope (specs 10–14): no missing APIs.**
- The factory counts match Python: 39 vectorizers, 4 multi-vector, 22 generative (+1 on main), 7 rerankers, and 22 per-query `GenerativeConfig` providers.
- Every enum member matches.
- Every query, generate, aggregate, data, batch, tenant, collection and config method signature is covered.
- Corrections applied:
  - `hybrid` has no `alpha_param` parameter (it's a wire field);
  - `GenerativeParameters.grouped_task` has no `debug`;
  - `NearMediaType.IMAGE` is included;
  - `batch.stream` has `consistency_level`;
  - the P2/P6 phase conflict for boost/diversity is resolved;
  - spec 10 contradicted itself on deprecated items (§14 is now authoritative everywhere);
  - the module counts are corrected.

**Client scope (09, 15): the admin APIs were exact**, with no path, status, wire key or gate mismatches. What was added or fixed:
- `client.integrations.configure()` (it was missing);
- `ClientClosedException` (implemented);
- the OIDC failure modes (`MissingScopeException`, etc.);
- the rule for when OIDC discovery runs (it runs even without credentials);
- `connect(force)` and `waitForWeaviate` labelled as PHP additions;
- the grpc-web deviation and error diagnosis;
- the token-refresh timing;
- a consolidated exception tree in [01](../01-architecture.md#errors), with one `TimeoutException` name.

**Unreleased in Python (🆕 in the matrix).** These exist on `main` but not in v4.23.1:
- `grpc_path_prefix` / grpc-web;
- `Configure.Generative.meta` / `GenerativeConfig.meta` / `MetaReasoningEffort`;
- `config.delete_vector_index` and `VectorIndex.none()`;
- `VectorFilterStrategy.PATHSEER` (server 1.40);
- `wait_for_vector_indexing` checking `per_node_status`.

They're planned, but they should be re-checked when Python 4.24.0 ships.
