# 05: Testing & CI

## Test layers

| Layer | Location | What it tests | Runs against |
|-------|----------|---------------|--------------|
| Unit | `tests/Unit` | Builders, filter and config serialization, mappers (domain ⇄ proto/JSON), gRPC framing, trailer parsing, retry policy, version gating, OIDC token refresh logic | A mocked PSR-18 client (`php-http/mock-client`) and a `FakeGrpcTransport` that records requests and replays canned protobuf replies |
| Contract | `tests/Contract` | Golden-file tests: a given PHP call produces a byte-identical protobuf `SearchRequest` or REST JSON body to what Python v4 produces for the same call | Fixtures generated by a small Python script (`tools/golden/generate.py`) that uses the Python client's request builders |
| Integration | `tests/Integration` | Real behaviour end to end | Weaviate in Docker (docker-compose) |
| Parity | `tests/Integration/Parity` | A PHP port of the Python client's `integration/` test suite | Same as integration |
| Examples | `examples/` + `tests/Examples` | Every example and docs snippet runs without errors | Same as integration |

**Contract tests** are the cheapest way to prove parity. If the PHP client sends the same bytes as Python, the server behaves the same way. Python's builders are the oracle.

**Parity tests** follow the file names of the Python suite so gaps are easy to spot. For example, `integration/test_collection_filter.py` becomes `CollectionFilterTest.php`. A CI script lists the Python integration files that have no PHP counterpart, and that list is posted on each PR.

## Docker environments

We reuse, or adapt, the compose files the Python client keeps under `ci/`:

- `docker-compose.yml`: a single node with modules (text2vec-contextionary or text2vec-transformers, generative-dummy, reranker-dummy). **No external API keys are needed in CI.**
- `docker-compose-rbac.yml`: API-key auth with RBAC enabled.
- `docker-compose-okta-*.yml` / Keycloak: OIDC flows.
- `docker-compose-backup.yml`: filesystem backend and MinIO for S3.
- `docker-compose-cluster.yml`: 3 nodes, for replication, consistency level and cluster tests.
- Tests that need cloud providers (OpenAI, Cohere and so on) are tagged `@group external`. They run nightly with secrets and are skipped on fork PRs.

Test isolation: each test makes a collection with a unique name (`Test_<class>_<method>_<rand>`) and deletes it afterwards. Tests can run in parallel with `paratest`.

## CI matrix (GitHub Actions)

| Job | Matrix |
|-----|--------|
| lint | PHP-CS-Fixer (dry run), PHPStan at max level, `composer validate`, `composer audit` |
| proto-drift | Regenerate the protos, then `git diff --exit-code` |
| unit + contract | PHP 8.2, 8.3, 8.4, 8.5 × `--prefer-lowest` / `--prefer-stable` × {ubuntu, windows (unit only)} |
| integration | PHP {8.2, 8.5} × transport {curl, ext-grpc} × Weaviate {1.29 (floor), and the latest patch of the last four minors} |
| integration-auth / backup / cluster | PHP 8.4 × curl × latest Weaviate |
| nightly | Weaviate `preview`/`main` image, `@group external`, benchmarks |
| integrations | `weaviate-laravel` against Laravel {11, 12, 13}; `weaviate-symfony` against Symfony {6.4 LTS, 7.x} |

Tests that need a feature newer than the server under test are skipped with `#[RequiresWeaviate('1.32')]`, a custom PHPUnit attribute that reads the server version once per run.

## Quality gates for merging

- All jobs green. Coverage of 85% or more lines in `src/` (generated `src/Proto` excluded), and no drop from `main`.
- New public API needs a unit test, an integration test, and a parity-matrix row update.
- A new server-dependent feature needs a version gate and a skip-marked test for older servers.

## Release process

- Releases are tagged `vX.Y.Z` and Packagist picks them up automatically from the webhook.
- The GitHub release notes come from Conventional Commits (`release-please` or `git-cliff`).
- Pre-1.0 releases follow the phases in [04](04-roadmap.md). After 1.0 we follow strict SemVer, and `@internal` namespaces are excluded.
