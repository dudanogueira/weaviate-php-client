# Security review (2026-09-25)

**Scope:**
- the whole client as of this date: `src/` (connection layer, REST, curl and ext-grpc gRPC transports, auth and exceptions);
- the shell scripts in `bin/`, the Docker files, `docker-compose.yml`, CI and dependencies;
- the public git history.

**Method:**
1. A manual threat-model review with exploit probes against local Weaviate 1.39.7, an RBAC server, and purpose-built malicious HTTP servers.
2. Automated tools:
   - `composer audit` (advisories), `composer outdated`;
   - **gitleaks** over the full git history;
   - a grep of the history for the real Weaviate Cloud cluster ID and key prefix used in testing;
   - **Semgrep** (`p/php`, `p/secrets`, `p/github-actions`, `p/dockerfile`);
   - `actionlint`.
3. Every fix has a regression test (`tests/Unit/Security/SecurityRegressionTest.php`). Mutation checks confirmed the tests fail when the fix is reverted.

## Verified OK (no change needed)

- **TLS verification is on everywhere.** A self-signed server is rejected by:
  - curl gRPC, on libcurl 7.88 with ALPN disabled and on 8.14;
  - Guzzle (cURL error 60);
  - ext-grpc (`CERTIFICATE_VERIFY_FAILED`).

  Nothing overrides peer or host verification. Disabling ALPN keeps VERIFYHOST and SNI. `https` plus HTTP/2 prior knowledge still negotiates TLS. The curl gRPC transport never follows redirects.
- **Proxy passwords don't appear in error messages.** Only the base URL is used, and PSR-18 exceptions aren't chained.
- **The earlier QA fixes hold:**
  - `__debugInfo` redaction;
  - CRLF/NUL header validation;
  - `ApiKey` blocks JSON, serialize and clone;
  - proxy env handling on all three transports;
  - the streaming gRPC size cap (enforced before decoding);
  - compressed gRPC frames rejected;
  - protobuf recursion limit 100, JSON depth 512;
  - timeouts always set and greater than 0.
- **No unsafe functions.** There's no `unserialize`, `eval` or shell execution in `src/`, `tests/` or `bin/`. `mktemp` is cleaned up by a trap, and `bin/php` passes credentials by environment-variable name only.
- **CI** runs on `pull_request` (not `pull_request_target`), with `permissions: contents: read`, and uses no secrets.
- **The public history** has no real cluster hostnames or keys. The only keys in the repo (`admin-key`, `norole-key`) are local test fixtures.

## Residual risks and backlog

- **Injected PSR-18 clients** are the caller's responsibility: turn off redirects, set timeouts and proxies (documented in the README).
- **The no-ALPN path on libcurl older than 8.12** is secure (TLS still verified) but could be rejected by strict-ALPN servers. That's a compatibility risk, not a security one ([spike 0001](../spikes/0001-grpc-transport.md), finding 6).
- **The Docker service images** are pinned by version tag, not digest. Dependabot covers the Dockerfiles; consider digests for release CI.
- **Re-run this review** when OIDC (token handling and refresh), TLS/mTLS configuration, gRPC-web and batching land. They add new credential and resource-handling paths.
